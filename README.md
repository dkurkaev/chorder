# Chorder

Прототип iOS-приложения: слушает фрагмент песни через микрофон и определяет **темп** и **аккорды**.
SwiftUI + SwiftData, весь анализ — локально на устройстве, без сети и сторонних зависимостей.

## Запуск

```bash
xcodegen generate          # создаёт Chorder.xcodeproj из project.yml
open Chorder.xcodeproj     # ⌘R на симуляторе или устройстве
```

Требуется Xcode 16+ и iOS 17+. Микрофон в симуляторе работает — он берёт вход с Mac.

## Импорт файла

Кроме микрофона запись можно завести из готового аудиофайла — так удобнее гонять
алгоритм на одном и том же материале:

- **Из Файлов и iCloud** — кнопка «Импортировать файл» под кнопкой записи.
- **Из Voice Memos и любого другого приложения** — «Поделиться» → Chorder.
  Отдельного API для чтения Voice Memos у iOS нет, поэтому приложение
  зарегистрировано как получатель аудио (`CFBundleDocumentTypes`).

Формат значения не имеет: файл декодируется, сводится в моно 22.05 кГц и обрезается
до минуты — как и запись с микрофона. Проверить импорт из консоли:

```bash
xcrun simctl openurl booted "file:///путь/к/фрагменту.m4a"
```

## Как это устроено

```
микрофон ──► AVAudioEngine ──► ресемпл 22.05 кГц моно ──► [Float]
                                                            │
                     ┌──────────────────────────────────────┴──────────────┐
                     ▼                                                     ▼
          FFT 8192 / hop 2048                                   FFT 1024 / hop 256
          спектральное отбеливание                              spectral flux
          пики → 12 классов высоты                              огибающая онсетов
                     │                                                     │
                     │                                       автокорреляция + приор 120 BPM
                     │                                                     │
                     │                                        DP beat tracking (Ellis)
                     │                                                     │
                     └────────► хрома, усреднённая по долям ◄──────────────┘
                                          │
                        Витерби по 72 шаблонам + «нет аккорда»
                                          │
                            аккорды → такты → SwiftData
```

| Файл | Отвечает за |
|---|---|
| `Sources/DSP/FFTProcessor.swift` | vDSP real-FFT, окно Ханна, амплитудный спектр |
| `Sources/DSP/ChromaExtractor.swift` | хромаграмма: отбеливание, выделение пиков, свёртка октав |
| `Sources/DSP/ChordRecognizer.swift` | 72 шаблона аккордов с обертонами, Витерби, разбор по долям |
| `Sources/DSP/BeatTracker.swift` | онсеты, темп, сетка долей, сильная доля |
| `Sources/DSP/KeyEstimator.swift` | тональность (Крумхансл — Шмуклер) |
| `Sources/Analysis/SongAnalyzer.swift` | оркестратор: хрома → ритм → аккорды → такты |
| `Sources/Audio/AudioRecorder.swift` | захват, уровень, спектр для визуализации, живой разбор |
| `Sources/Audio/AudioImporter.swift` | импорт готового файла: ресемпл, стерео → моно, обрезка до минуты |
| `Sources/Storage/` | SwiftData-модель записи + хранение `.caf` |
| `Sources/Views/` | SwiftUI: экран записи, результат, библиотека |

### Ключевые решения

- **Спектральное отбеливание** в хроме обязательно для микрофона: шум комнаты поднимает
  весь спектр, из-за чего хрома становится плоской и аккорд неотличим от шума.
- **Разбор по долям** (beat-synchronous chroma): хрома усредняется внутри доли, поэтому
  границы аккордов ложатся на сетку ритма, а не «дрожат» каждые 90 мс.
- **Учёт тональности**: диатонические аккорды получают фору 6% — убирает случайные
  внедиатонические срабатывания.
- **Словарь аккордов**: maj, min, 7, m7, maj7, dim во всех 12 тональностях.

## Проверка DSP без Xcode

Тот же конвейер собирается в консольную утилиту:

```bash
./Tools/DSPCheck/run.sh              # синтетический фрагмент C — Am — F — G, 120 BPM
./Tools/DSPCheck/run.sh noisy        # он же с шумом комнаты и полосой микрофона
./Tools/DSPCheck/run.sh запись.caf   # реальный файл + диагностика хромы
PENALTY=6 ./Tools/DSPCheck/run.sh запись.caf   # подбор штрафа за смену аккорда
```

Записи из симулятора лежат в контейнере приложения:

```bash
open "$(xcrun simctl get_app_container booted com.chorder.app data)/Documents/Recordings"
```

## Что дальше

- Проверить точность на записях с известными аккордами и подкрутить пороги.
- Размер такта пока фиксирован 4/4; определение 3/4 и 6/8 — следующий шаг.
- Аккорды с басом (`C/G`), sus и увеличенные не распознаются.
- Экспорт разбора (текст / MIDI) и метроном под найденный темп.
